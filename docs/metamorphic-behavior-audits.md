# Metamorphic behavior audits

Agent evaluations often have no single correct answer. A useful release check is to
run a baseline case and a deliberately transformed case, then test the relationship
between their observable behaviors.

`agent_reliability.metamorphic` supports two relations:

- `invariant`: a semantics-preserving transformation, such as whitespace, phrasing,
  or irrelevant context, must not change protected behavior.
- `responsive`: a meaningful policy or constraint change must alter every required
  behavior dimension and may alter only explicitly allowlisted dimensions.

The audit compares tool order, canonical JSON arguments, tool success states,
evidence IDs, escalation, and presence of an error. It intentionally excludes final
answer wording, latency, and cost; the core evaluator already measures those, while
this audit is designed to detect routing sensitivity and overreaction.

```python
from agent_reliability.metamorphic import (
    BehaviorDimension,
    MetamorphicPairSpec,
    MetamorphicRelation,
    audit_metamorphic_behavior,
)

pair = MetamorphicPairSpec(
    pair_id="require-human-review",
    baseline_case_id="standard-transfer",
    transformed_case_id="high-risk-transfer",
    relation=MetamorphicRelation.RESPONSIVE,
    required_changes=frozenset({BehaviorDimension.ESCALATION}),
    allowed_changes=frozenset({BehaviorDimension.ESCALATION, BehaviorDimension.TOOL_SEQUENCE}),
)
report = audit_metamorphic_behavior([pair], recorded_traces)
assert report.passed
```

## Evidence and failure behavior

Reports are deterministic and JSON-ready. Each pair includes a SHA-256 digest over
its contract and normalized behavior projections. The report contains stable finding
codes, not tool arguments, exception text, prompts, or answers. Missing traces and
malformed trace artifacts reject the pair. Duplicate IDs, invalid contracts, and pair
count violations reject the entire audit as malformed input.

Tool arguments must be interoperable JSON. The audit rejects cycles, non-string
object keys, non-finite numbers, integers outside the exact IEEE-754 range, Python-only
values, and configured byte/depth/node budget overruns. When tool sequences differ,
the sequence is the reported change; arguments and outcomes are not double-counted
across incomparable call positions.

## Trust boundary and limitations

This utility audits supplied traces; it does not prove the trace producer is honest.
Production evidence should be generated by an isolated runner, bound to model,
prompt, tool-schema, and policy versions, and stored immutably. The SHA-256 field is a
content identity, not an authenticity signature.

Relations and allowlists must be specified before inspecting candidate results.
Poorly chosen transformations can pass while missing real failures, and many related
pairs can create misleading confidence. Calibrate transformations by risk tier, keep
held-out transformation families, and combine this audit with task correctness,
safety, statistical uncertainty, latency, and cost gates. A future increment should
add signed run-manifest lineage and group-sequential confidence controls for repeated
release decisions.
